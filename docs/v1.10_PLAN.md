# v1.10 Plan: Global Flags Anywhere & UX Polish

## Overview
Version 1.10 will focus on relaxing the strict CLI argument ordering enforced in v1.9.0. The goal is to allow global flags (like `--quiet`, `--verbose`) to appear anywhere in the command line (before or after subcommands), improving user experience and matching conventions of tools like `ripgrep` or `curl`.

## Key Features

### 1. Global Flags Anywhere
**Current State (v1.9.0):**
Strict ordering: `exe [global-flags] [subcommand] [args]`
Example: `llm-cost --verbose estimate ...` (Works)
Example: `llm-cost estimate --verbose ...` (Fails or passed to subcommand)

**Target State (v1.10):**
Flexible ordering: Global flags can be interleaved.
Example: `llm-cost estimate ... --verbose` (Works)

**Implementation Strategy:**
- Refactor `src/cli/args.zig`.
- Use a two-pass parser or a "peek" strategy?
- Or, when parsing subcommand args, if a known global flag is encountered, bubble it up?
- Note: Subcommands currently handle their own args. We might need a unified parser that strips global flags from the raw `argv` before dispatching, or pass a "flag sink".

### 2. Other Candidates
- **Enhanced Visualizations**: More TUI elements?
- **Cloud Pricing Integration**: Direct API fetch for latest prices?

## Migration Guide
No breaking changes expected for users following v1.9.0 best practices.
Scripts using `v1.9.0` strict syntax will continue to work.
