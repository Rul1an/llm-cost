# llm-cost calibrate

The `calibrate` command allows you to compare your estimated LLM costs against actual billing data (FOCUS v1.0 CSV) to calculate drift, generate calibration factors, and verify pricing assumptions.

## Quickstart

```bash
# 1. Export estimates from your codebase
llm-cost export --format=json > estimates.json

# 2. Get your actuals (e.g. download CSV from your FinOps tool)
# Ensure it follows FOCUS v1.0 standard columns.
# Required columns: ResourceId, BilledCost, ChargePeriodStart

# 3. Run calibration
llm-cost calibrate \
  --estimates estimates.json \
  --csv billing-data.csv \
  > factors.toml
```

## Input Formats

### 1. Estimates (`--estimates`)
A JSON file mapping `ResourceId` to cost details. This is usually generated by `llm-cost export`.

**Format:**
```json
{
  "trace-123": {
    "cost": 1500,
    "model": "gpt-4",
    "scenario": "chatbot"
  },
  "trace-124": { ... }
}
```
*   `cost`: Estimated cost in MicroUSD ($0.000001).
*   `model`: The model ID used.
*   `scenario`: A tag for grouping (e.g., "prod", "analysis").

### 2. Actuals (`--csv`)
A CSV file adhering to the [FOCUS v1.0 Specification](https://focus.finops.org/).

**Required Columns:**
*   `ResourceId`: Unique ID matching the keys in your estimates JSON.
*   `BilledCost`: The final cost charged by the provider.
*   `ChargePeriodStart`: Date of the charge (ISO8601).

**Optional "x-" Columns:**
*   `x-call-count`: Number of API calls aggregated in this row (used for confidence weighting).
*   `x-cache-hit-ratio`: Cache hit ratio (0.0 to 1.0) for this row.

### Privacy Note
The tool only extracts `ResourceId`, `BilledCost`, and explicitly allow-listed tags (`model`, `scenario`, `x-*`). All other columns and metadata in the CSV are ignored and never leave your machine. No telemetry is sent.

## Output (`factors.toml`)

The command outputs a TOML file containing calibration factors for each Model/Scenario pair.

```toml
[[factor]]
model = "gpt-4"
scenario = "chatbot"
multiplier = 1.0500      # Actuals are 5% higher than estimates
drift_bps = 500          # +500 basis points drift
confidence = "high"      # Based on sample size (>100 samples)
samples = 1250
```

### Applying Factors
You can use this file to adjust future estimates or update your `llm-cost.toml` configuration to apply these multipliers automatically.

## Matching Rules (`--match`)

*   `strict` (default for CLI): `ResourceId` must match exactly (case-sensitive).
*   `fuzzy`: Attempts to strip common prefixes (e.g., `custom-`, `llm-cost/`) from the CSV ResourceIds to find a match in your estimates.

> **Note**: When using the CLI, `strict` is the default matching mode if you do not specify `--match`.

## Join Semantics

The calibration process performs a **Streaming Left Join** (Estimates + Actuals -> Factors).

1.  **Normalization**: Both Estimates and Actuals `ResourceId`s are normalized based on `--match` mode (`strict` or `fuzzy`).
2.  **Aggregation**:
    *   Multiple Actuals rows matching a single Estimate ID are **SUMMED**.
    *   Example: Estimate `req-1` ($1.00) vs Actuals `req-1` (Jan 1, $0.50) + `req-1` (Jan 2, $0.60).
    *   Result: Estimate $1.00 vs Actual $1.10. Drift +10%.
3.  **Grouping**: Results are grouped by unique `(model, scenario)` pairs from the **Estimates**.
    *   Drift = (Sum of Actuals for Group / Sum of Estimates for Group) - 1.

## Troubleshooting

| Issue | Cause | Solution |
| :--- | :--- | :--- |
| **Error: DuplicateField** | Your `estimates.json` contains duplicate IDs, OR you have a **Fuzzy Match Collision** (e.g. `foo` and `custom-foo` both normalize to `foo`). | Remove duplicates or use distinct IDs that don't collide after prefix stripping. |
| **Error: CSV missing required columns** | Your CSV lacks `ResourceId`, `BilledCost`, or `ChargePeriodStart`. | Ensure your CSV matches FOCUS v1.0 spec. |
| **Warning: 0 rows matched** | No rows in your CSV matched any ID in your estimates. | Check `ResourceId` formats. Try `--match fuzzy`. Ensure coverage periods overlap. |
| **Drift is 0 bps** | Exact match or comparing estimates to themselves. | Verify you are using the correct actuals CSV. |
| **Error: TooManyGroups** | Unique `(model, scenario)` pairs > 100k. | Filter your input or consolidate tags. |
